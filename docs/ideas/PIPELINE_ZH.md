# 新流程：先静态、再运动、视觉选优

## 数据与风格

- 任务沿用 [5,000 题](../../data/tasks5000/README.md)，训练只用 4,750 题；250 题即使生成也必须留出。
- 参考 3DrawAgent 的可识别线稿风格，表达采用 Three.js r180；并非官方算法或成绩复现。
- 黑色、不透明、世界坐标管线半径 0.008；禁用像素细线及逐笔调宽。
- 保留完整三维体积；用语义注释和命名 THREE.Group 组织部件；刚体围绕局部支点整体变换。
- 少细节、无笔画数下限；24/36 是单主体/多主体软预算，不可因此漏画必要部件。

## 生成（原始提示词随仓库提供）

1. 动画任务 → [首帧描述](../../prompts/static_motion_v2/describe_system.txt)，只解释动作开始前状态。
2. 原任务＋首帧描述 → [静态完整 JS](../../prompts/static_motion_v2/static_system.txt)，DeepSeek low thinking；render(t) 在所有时刻保持同一场景。
3. 原任务＋静态 JS → [补运动完整 JS](../../prompts/static_motion_v2/motion_system.txt)，保留几何，t=0 必须复现静态；柔性部件允许变形但保持连接。

概念上是静态/运动两阶段，连同描述提取共有三次 API 调用。
当前大批量只做步骤1—2和视觉选优，不自动做步骤3，不自动训练。
保留原始 reasoning、JS、usage、请求与响应；这轮未启用历史 reasoning 压缩流程。
接口仍为 function createAnimation({THREE,scene,camera}) 返回 {render(t)}。

## 视觉选优

- 每题比较旧/新候选；从零复现时独立生成两个候选，旧候选不能绕过新风格门槛。
- 先检查可执行、非空、有限坐标、统一线宽、透明度及静态一致性。
- 四个对应固定视角，384×384/视角，组成768×808小图；A/B顺序打乱。
- [DeepSeek视觉评审](../../prompts/static_motion_v2/judge_system.txt) 使用 no thinking，只看任务、首帧描述和图，不看源代码或 reasoning。
- 既要相对选优，也要独立判断可接受性；低置信度或两者都差时最多补两次，否则隔离。
- 技术不合格不送视觉评审；基础设施错误应恢复环境后重跑，不能当作模型质量失败。
- 当前服务器渲染12并发、select上限1000，二者独立；并发上限不等于活跃请求数。
- 401/402/403、磁盘不足时暂停；保留在途响应与断点，避免无限付费重试。

## 已知边界

原风格的两阶段8题通过首帧保持检查，不代表所有动作正确；统一线宽新版也有独立小批验证。
最新服务器12条小图渲染通过约2.2秒，这是环境测速，不是视觉质量成绩。
新生成完成4,998题不等于选出了4,998条高质量样本；选优尚未结束。
公开仓库提供方案和精确提示词，尚未提供上述新流程的独立启动脚本；根目录 run.py 仍只运行历史 one-shot。
